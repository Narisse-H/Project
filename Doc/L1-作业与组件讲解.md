# 第 0 部分：组件地图（先看全景，别急着学）

WPF 的组件不是并列的，是**一层支撑下一层**。L1 只碰中间四层，其余先知道名字就行。

| # | 组件 | 一句话 | 本课 |
| --- | --- | --- | --- |
| C1 | XAML / code-behind | 一个类被拆成两个文件，XAML 负责"长什么样" | ✅ 必学 |
| C2 | 元素树与布局面板 | 界面是一棵树，`Grid`/`StackPanel` 负责排列 | ✅ 必学 |
| C3 | DependencyProperty（依赖属性） | WPF 里"能被绑定/样式/动画"的属性基座 | ✅ 概念必懂 |
| C4 | Binding（绑定） | 把 UI 属性和数据属性"连一根线" | ✅ 核心 |
| C5 | DataContext | 每个元素"默认去哪个对象上找数据" | ✅ 核心 |
| C6 | INotifyPropertyChanged | 数据变了怎么通知 UI 刷新 | ✅ 核心 |
| C7 | ICommand / RelayCommand | 按钮点击怎么反过来调用 VM 的方法 | ✅ 核心 |
| C8 | ObservableCollection | 列表类数据，增删自动刷新 UI | ⬜ L5 前后 |
| C9 | Style / ControlTemplate / DataTemplate | 统一外观、定义"数据怎么画" | ⬜ L6 |
| C10 | IValueConverter | 绑定路径上的"格式转换插头" | ⬜ 需要时 |
| C11 | Dispatcher / UI 线程 | 只有 UI 线程能改控件 | ⬜ L4 遇到 |
| C12 | Application / 生命周期 | 程序从哪启动、窗口怎么开 | ⬜ L2 |

记住这张图：**C4~C7 就是"MVVM"四个字的全部内容**。MVVM 不是什么框架，就是"用这四样东西把界面和数据拆开"的一种习惯。

# 第 1 部分：组件逐个讲（C1 ~ C7）

## C1. XAML 与 code-behind —— 一个类，两个文件

**它是什么**：`MainWindow` 这个类被 `partial`（部分类）拆成两个文件：
- `MainWindow.xaml` —— 声明式地描述界面
- `MainWindow.xaml.cs` —— 写逻辑（事件响应、初始化）

**靠什么粘在一起**：XAML 根节点上的 `x:Class="ProjectEditor.MainWindow"` 指明"我属于哪个类"。

**没它会怎样**：你得像 WinForms 一样用 `new Button()` 一行行拼界面，改个间距都要重新编译看效果。

**关键机制（重要，新手必知）**：
1. 编译时，XAML 被编译成 BAML 塞进程序集（所以发布时你只看到 `.dll`，看不到 `.xaml` 源文件）。
2. `InitializeComponent()` 是编译器**生成**的方法，它做两件事：加载 BAML、把 `x:Name="xxx"` 的控件赋值给同名字段。
3. 所以：

```csharp
// MainWindow.xaml 里如果有 <TextBox x:Name="NameBox" />
// 那么 MainWindow.xaml.cs 里就能直接写：
NameBox.Text = "hello";     // NameBox 是编译器生成的字段
```

**坑**：
- 改了 `x:Name` 而代码里还在用旧名字 → 编译错误。这不是玄学，是字段没生成。
- `InitializeComponent()` 之前访问 `x:Name` 的控件 → `NullReferenceException`。所以任何"初始化时要碰控件"的代码，都写在 `InitializeComponent()` 之**后**。

## C2. 元素树与布局面板 —— 界面是一棵树

**它是什么**：XAML 的嵌套关系 = 控件的父子树。`<Window>` → `<Grid>` → `<StackPanel>` → `<TextBlock>`。

**没它会怎样**：没有布局系统，你得手算每个控件的像素坐标（WinForms 的老路子），窗口一缩放全乱。

**L1 只需要认识两个面板**：

| 面板 | 行为 | 什么时候用 |
| --- | --- | --- |
| `StackPanel` | 按顺序竖着/横着摞，**不管剩余空间** | 一列控件简单堆叠 |
| `Grid` | 用行列切格子，支持 `*`（按比例分剩余空间） | 需要"铺满/对齐/分栏" |

```xml
<Grid Margin="16">
    <Grid.RowDefinitions>
        <RowDefinition Height="Auto"/>   <!-- 按内容高度 -->
        <RowDefinition Height="*"/>      <!-- 吃掉剩余空间 -->
        <RowDefinition Height="Auto"/>
    </Grid.RowDefinitions>
</Grid>
```

**坑**：`Height`/`Width` 写死数字（如 `Width="800"`）是最常见的"界面很丑"的原因。想让它跟着窗口变，就别写死，用 `*` 和 `Margin`/`Padding`。

---

## C3. DependencyProperty —— WPF 的属性地基

**它是什么**：WPF 控件的绝大部分属性（`Text`、`Width`、`Background`…）不是普通 C# 属性，而是**依赖属性**：注册在静态表里、带默认值、能被绑定/样式/动画/继承改写。

```csharp
// WPF 内部大致长这样（你不用写，认识就行）
public static readonly DependencyProperty TextProperty =
    DependencyProperty.Register("Text", typeof(string), typeof(TextBox),
        new PropertyMetadata(string.Empty));
```

**为什么必须懂它**（一句话版）：**普通 C# 属性不能参与绑定**。你后面写的 ViewModel 属性是普通属性——这没问题，因为绑定要求的是**源**有通知（C6），而**目标**必须是依赖属性。`TextBlock.Text` 是依赖属性，所以能当绑定的目标。

**没它会怎样**：不存在"样式统一改外观""动画""属性值继承"这些 WPF 的核心能力。

**L1 你只需要记住**：能绑定的目标属性 = 控件属性（依赖属性）；`x:Name` 和 `Binding` 用的都是这类属性。

---

## C4. Binding —— 把界面和数据连一根线

**它是什么**：一条"数据管道"，把源对象的某个属性，同步到控件的某个属性。

```xml
<TextBlock Text="{Binding Name}" />
```

这条线有 **4 个要素**，务必背下来：

| 要素 | 含义 | 例子 |
| --- | --- | --- |
| 目标（Target） | 控件上的属性 | `TextBlock.Text` |
| 目标属性（TargetProperty） | 同上，被绑定的那一个 | `Text` |
| 源（Source） | 数据对象 | `DataContext`（C5） |
| 源路径（Path） | 源对象上的属性名 | `Name` |

语法细节：

```xml
{Binding Path=Name, Mode=OneWay}                    <!-- 源 → UI，默认 -->
{Binding Path=Name, Mode=TwoWay}                    <!-- 双向 -->
{Binding Path=Name, Mode=OneWay, FallbackValue="空"} <!-- 拿不到值时显示什么 -->
```

**⚠️ 本课最大的坑：`UpdateSourceTrigger`**

`TextBox.Text` 默认是 `UpdateSourceTrigger=LostFocus` —— 意思是**你打字的时候 VM 根本没收到新值**，必须等焦点离开输入框才更新。第一次做 L1 一定会被这个绊住。

```xml
<TextBox Text="{Binding Name, UpdateSourceTrigger=PropertyChanged}" />
```

改成 `PropertyChanged` 才是"打一个字，立刻同步"。

**坑**：
- 绑定写错了**不会报编译错误**，只会静默失败（UI 显示空白）。因为这是运行期的反射查属性。
- `{Binding Name}` 的 `Name` 拼错 → 同样静默。绑定的调试手段见第 4 部分。

---

## C5. DataContext —— 绑定默认去哪个对象上找

**它是什么**：每个元素都有一个 `DataContext` 属性。当 `Binding` 不写 `Source` 时，就**顺着元素树往上找最近的祖先的 `DataContext`**，把它当作源。

```csharp
// MainWindow.xaml.cs
public MainWindow()
{
    InitializeComponent();
    DataContext = new MainViewModel();   // 这一行是 MVVM 的"接电"
}
```

**为什么重要**：`DataContext = new MainViewModel()` 这一行，是"View 和 ViewModel 建立关系"的全部秘密。L1 你手写它就是够的，L2 换成 DI 容器注入的，机制完全一样。

**关键细节**：
- `DataContext` 是**继承的**。你设在 `Window` 上，里面所有控件都能用，不用逐个设置。
- `{Binding}`（路径为空）= 绑定 `DataContext` 本身。

**坑**：
- 忘了设 `DataContext` → 所有绑定全部静默失败，界面一片空白。**这是 MVVM 新手第一大事故，先怀疑它。**
- 在 `InitializeComponent()` 之前设 `DataContext` → 不报错但可能引发奇怪问题，养成"放后面"的习惯。

---

## C6. INotifyPropertyChanged —— 数据变了，怎么让 UI 知道

**它是什么**：一个只有一个成员 `event PropertyChangedEventHandler? PropertyChanged` 的接口。

**没它会怎样**：绑定是"一次性快照"——初始值能显示，之后你在代码里改属性，界面**永远不动**。这是新手第二个高频困惑："我明明改了值，界面为什么不刷新？"

**机制**：WPF 在建立绑定时，检查源对象是否实现了 `INotifyPropertyChanged`。实现了，就订阅事件；你 raise 事件并带上属性名，它就去重新读一次那个属性。

**手写样板**（这段是纯样板，可以直接照抄，重点在"什么时候 raise"）：

```csharp
using System.ComponentModel;
using System.Runtime.CompilerServices;

public class MainViewModel : INotifyPropertyChanged
{
    public event PropertyChangedEventHandler? PropertyChanged;

    private void OnPropertyChanged([CallerMemberName] string? propertyName = null)
        => PropertyChanged?.Invoke(this, new PropertyChangedEventArgs(propertyName));

    private string _name = "";
    public string Name
    {
        get => _name;
        set
        {
            if (_name == value) return;   // 值没变就别通知，省性能也省麻烦
            _name = value;
            OnPropertyChanged();          // [CallerMemberName] 自动填 "Name"
        }
    }
}
```

**关键点**：
- `[CallerMemberName]` 让编译器自动把属性名填进去，不用手写字符串（也就不会拼错）。
- 「值相等就 return」这个判断不是必须的，但养成习惯，能避免无限循环类的怪问题（后面做双向绑定时尤其重要）。

## C7. ICommand —— 按钮点击，怎么反过来调用 VM

**它是什么**：`System.Windows.Input.ICommand`，三个成员：

```csharp
public interface ICommand
{
    bool CanExecute(object? parameter);   // 现在能不能执行（决定按钮灰不灰）
    void Execute(object? parameter);      // 执行
    event EventHandler? CanExecuteChanged; // 通知 WPF 重新问一次 CanExecute
}
```

**为什么不用事件**：如果按钮用 `Click="OnClearClick"`，那逻辑就留在 code-behind 里，ViewModel 没法独立测试、也没法复用到别的视图。`Command` 让"点哪个按钮 → 调哪个方法"变成一个**可绑定的属性**。

```xml
<Button Content="清空" Command="{Binding ClearCommand}" />
```

**没资质的坑**：`CanExecute` 返回 `false` 时按钮会自动变灰，你不用写一行"禁用"代码——这就是命令的精髓。

**手写 RelayCommand 样板**（同样是管道代码，可照抄；想彻底懂就把 `CommandManager` 那行查一下）：

```csharp
using System.Windows.Input;

public class RelayCommand : ICommand
{
    private readonly Action<object?> _execute;
    private readonly Func<object?, bool>? _canExecute;

    public RelayCommand(Action<object?> execute, Func<object?, bool>? canExecute = null)
    {
        _execute = execute;
        _canExecute = canExecute;
    }

    public bool CanExecute(object? parameter) => _canExecute?.Invoke(parameter) ?? true;
    public void Execute(object? parameter) => _execute(parameter);

    // 绑定到 WPF 的全局重新求值信号，这样输入变化后按钮灰/亮会自动跟着变
    public event EventHandler? CanExecuteChanged
    {
        add => CommandManager.RequerySuggested += value;
        remove => CommandManager.RequerySuggested -= value;
    }
}
```

`CommandManager.RequerySuggested` 是 WPF 的"全局重算"信号——键盘输入、焦点变化时它会触发，WPF 就重新调一遍所有 `CanExecute`。这解释了 C7 里"为什么按钮会自己灰掉/亮起来"。

public partial class MainViewModel : ObservableObject

# 第 3 部分：ViewModel 设计的三条铁律（L1 就开始遵守）

1. **ViewModel 不引用控件、不引用 `System.Windows`**。需要弹窗？用 C7 之外的"服务接口"抽象（L5 讲）。这一条决定了你的代码能不能写单元测试。
2. **UI 上显示的一切，都应该来自 ViewModel 的属性**。code-behind 里只允许出现 `InitializeComponent()`、`DataContext = ...`、以及纯视觉代码（如拖拽）。
3. **绑定目标永远是公共属性**（`public`），字段、私有属性都绑不上，且静默失败。

---

# 第 4 部分：怎么调试"绑定静默失败"

绑定的错误**不会**出现在终端里，它走 WPF 的 Trace 通道（Warning 级）。

- 最简单的办法：装微软官方小工具 **DebugView**（Sysinternals），运行时看它输出的 `System.Windows.Data Error: 40 ...`，会直接告诉你"哪个 Binding 找不到哪个属性"。
- 临时土办法：在 `App.xaml.cs` 里加 `System.Diagnostics.PresentationTraceSources.DataBindingSource.Switch.Level = System.Diagnostics.SourceLevels.Warning;`，配合 TraceListener 写文件。

**没有这个手段时，你的排错顺序是**（按命中率排）：
1. `DataContext` 设了吗？（最高频）
2. 属性名拼对了吗？大小写？
3. 属性是 `public` 吗？
4. 源对象实现 `INotifyPropertyChanged` 了吗？
5. 是不是 `TextBox` 的 `UpdateSourceTrigger` 没改成 `PropertyChanged`？
